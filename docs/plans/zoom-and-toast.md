# 設計: + / = / - によるズームと倍率トースト

ステータス: 実装済み。WebKitのページ読み込みを伴うテストと実機での表示確認は未完了（下記参照）。

## 要件

| キー | 動作 |
|---|---|
| `+` | ズームイン |
| `=` | 100%に戻す |
| `-` | ズームアウト |

倍率を変更したら、表示領域の右上に現在の倍率を3秒間表示する。

以下の倍率範囲・刻み・保持範囲は、未指定の部分に対する初案。

## 操作仕様

- 初期値100%、10ポイント刻み、最小50%、最大200%。`100 → 110 → 120` のように加減算する。
- `=` は現在の倍率にかかわらず100%へ戻す。
- キーリピートに対応する。上限・下限では倍率を変更しない。
- 100%での `=` や上限・下限への追加操作はキーを消費するが、トーストの表示・延長はしない。
- `KeyboardEvent.key` の文字で判定し、物理キー位置には依存しない。`+` を入力するためのShiftは許可する。`=` はリセット専用で、拡大の別名にはしない。
- Command / Control / Option付き、IME変換中は対象外。
- Web本文にフォーカスがある通常モード・`v`・`V`モードで有効。モード、キャレット位置、選択範囲を維持する。
- インライン編集、変更前ソース表示のtextarea、その他のinput / textarea / contenteditable内では文字入力を優先する。ネイティブの検索・ファインダー・リクエスト入力中もズームしない。
- `Space` 等のプレフィックス待機中でもズームを単独操作として処理し、プレフィックスを解除する。
- 同一ウィンドウ内のファイル切替・再描画・ライブリロードでは倍率を保持する。ウィンドウを隠して再表示しても保持し、新しいViewerViewControllerは100%から開始する。ディスクへの保存は行わない。
- Markdownとコード表示の双方に適用する。ファイル未表示時は操作を受け付けない。

## 表示の対象

WebView全体（本文、目次、コード、表、画像、Mermaid、Web側のカーソル・変更マーカー）を拡大する。文字だけでなく余白を含むページズームとする。

ツールバー、ネイティブ検索バー、ファインダー、リクエストパネル、トーストの大きさは一定に保つ。ネイティブのズームには `WKWebView.pageZoom` を使い、CSSのtransformや文字サイズ変更を重ねない。

Appleの仕様では `pageZoom` の既定値は1.0で、Webコンテンツ全体を拡縮する。
参照: [Apple: WKWebView.pageZoom](https://developer.apple.com/documentation/webkit/wkwebview/pagezoom)

## トースト

- 表示文字は `Zoom 110%`。リセット時は `Zoom 100%`。
- WebView上端・右端から各16pt内側。検索バーが表示中なら、その下端から8pt下に置き、重なりを避ける。
- `NSVisualEffectView`（`.popover`）、角丸8pt、内側余白は縦8pt・横12pt。ラベルは13ptの等幅数字・標準ラベル色。ライト／ダークに追従する。
- フォーカスを移動せず、マウス操作を透過する。背後のリンクやスクロール操作を妨げない。
- 倍率を適用した時点で表示し、最後に倍率が変わってから3,000ms後に非表示にする。アニメーションは初版では付けない。
- 連打時は1個のトーストを更新し、古い非表示処理をキャンセルして期限を更新する。古い処理が新しい表示を消さないよう世代番号も確認する。
- ファイルを切り替えても残りの表示時間は継続する。ウィンドウを閉じる／隠すときはトーストを消し、タイマーを破棄する。再表示時に古いトーストを再表示しない。
- アクセシビリティでは現在の倍率を読み取れる静的テキストにする。

## 実装の責務

### JavaScript: キー受付とレイアウト補正

`markdown_renderer.js` の既存keydown処理に合わせる。

1. 既存の修飾キー・IME除外に加え、ズーム操作では入力要素を対象外にする。
2. `bindings` に `+` / `=` / `-` を追加する。送信するメッセージは `{type: "zoom", action: "in" | "reset" | "out", revision}`。
3. 倍率の値はJS側に保持しない。Swift側の値を唯一の基準とする。
4. 倍率適用後に呼べる `refreshAfterZoom()` を公開する。レイアウト反映後に `layoutReviewMarks()` と `drawCursor(false)` を実行する。カーソルを画面内に入れるための自動スクロールは行わない。

ズームでMarkdownを再レンダリングしない。`setDocument` や `placeCaret` は選択モードをリセットするため呼ばない。画像・Mermaidのソース読み込みもやり直さない。

### Swift: 倍率管理と適用

`ZoomState` を新規追加し、`percent: Int` を保持する。`apply(action:) -> Bool` で加減算・クランプを行い、倍率が変化したかを返す。`pageZoom` への変換は `CGFloat(percent) / 100`。整数管理により表示値と内部値のずれを防ぐ。

`ViewerViewController` に状態を保持し、既存の `userContentController(_:didReceive:)` にzoom分岐を追加する。

1. action・revisionを検証し、文書があり、`isEditingText == false`、`requestPanel.isHidden`、`fileFinder.isHidden`、firstResponderがNSTextViewでないことを確認する。検索バーは表示中でも本文にフォーカスがあれば許可し、ファインダー・リクエストパネルは表示中なら禁止する。未知のactionや古いrevisionは無視する。
2. `ZoomState` を更新し、変化がなければ終了する。
3. `webView.pageZoom` を即時更新し、トーストを更新する。JS完了待ちで後続のキー入力をブロックしない。
4. JSの `refreshAfterZoom()` を呼ぶ。JS側ではrequestAnimationFrameで更新をまとめ、連打時の古い補正を残さない。resizeやResizeObserverからの既存処理とも最終的に同じ座標に収束させる。

初版ではスクロール位置を独自に復元せず、WebKitのページズームに任せる。キャレット・選択のDOM位置を維持することを保証し、同じピクセル位置への固定は保証しない。長文途中で極端に先頭へ飛ぶ場合は受け入れ不可とし、実装時の実機確認で補正の必要性を判断する。

### Swift: トーストの独立View

`ZoomToastView` を新規追加し、表示・期限更新・非表示を担当させる。倍率計算や文書状態は持たせない。

`ViewerViewController.loadView()` でWebViewより前面に追加する。検索バー表示に応じて上端の制約を切り替える。`hitTest` はnilを返し、ラベルもフォーカスを取らない。非表示用TaskまたはWorkItemを1つ保持し、更新・終了時にキャンセルする。

既存の `windowShouldClose` はウィンドウを隠す実装のため、controllerの破棄だけに後始末を依存させず、closeボタンと `q` キーの両方のorderOut経路に非表示・タイマー解除を接続する。

## 検証と完了条件

### 自動検証

- `100 → + → 110 → - → 100`、任意の倍率から `= → 100`、50%と200%のクランプ。同じ値への操作が「変更なし」になること。
- 3キーが期待したメッセージを送り、イベントを消費すること。`Shift`付きの `+`、プレフィックス待機中の操作も確認する。
- Command / Control / Option付き、IME変換中、input / textarea / contenteditable内ではズームメッセージを送らず、文字入力を妨げないこと。
- 倍率変更後も `v` / `V` のモードと選択範囲が保持されること。
- トーストは倍率と一致し、3秒未満では表示、期限後に非表示。連打で古い期限を過ぎても消えず、最後の更新から3秒で消えること。時計／スケジューラを差し替えて実時間の待機を避ける。
- 値が変わらない操作で表示期限が延長されないこと。hide／close時に解除され、古い処理が再表示後の新しいトーストを消さないこと。
- controller経由の操作が実際の `pageZoom` に反映され、ファイル切替・再描画後も保持されること。古いrevisionと未知のactionは無視されること。
- `swift test` で既存テストも通ること。

### 実機確認

1. 長文の途中で `+` / `-` / `=` を操作し、本文・目次・画像・Mermaid・表が拡縮されること。読んでいた箇所から極端に飛ばないこと。
2. 50%・200%でキャレット、選択、変更マーカーの位置が本文に合うこと。`h/j/k/l`、表内移動、`v/V`による選択が継続して使えること。
3. トーストが右上に3秒表示され、連打時も1個だけ表示されること。文字・余白の大きさが倍率に依存しないこと。
4. 検索バーを表示して本文へフォーカスを戻し、ズーム時にトーストが検索バーと重ならないこと。
5. インライン編集、検索、ファインダー、リクエスト欄、変更前ソース内のキーがズームを起動しないこと。
6. ファイル切替・ライブリロード後も倍率が維持され、ウィンドウを隠して再表示するとトーストだけ消えていること。
7. ライト／ダーク、狭いウィンドウ、トーストの背後のクリック・スクロールを確認する。
